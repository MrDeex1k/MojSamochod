# Dependency patches

NUB applies version-specific patches through `package.json`'s
`patchedDependencies`. Install with `nub run deps:install`, which uses Socket
Firewall. Review each patch when upgrading its package.

The former `@shadcn/lint@0.2.1` theme-vocabulary patch was retired when upgrading
to 0.2.3. The unpatched validator accepts the current spacing/radius contracts,
and the project's lint check passes without the workaround.

## Expo SDK 58 / React Native 0.88 SwiftPM

The community-module patches add manifests generated by React Native's SwiftPM
scaffolder for DateTimePicker, Masked View, Gesture Handler, and Screens.
They also preserve the scaffolded Objective-C prefix header.
Safe Area Context 5.10.1 supplies its own upstream SwiftPM manifest, so its former
local manifest patch is removed. Its replacement patch only adds include guards
to the three unguarded edge/mode headers that Clang imports multiple times during
the SwiftPM Objective-C build; it does not replace the upstream manifest.
DateTimePicker, Masked View, and Gesture Handler need explicit module maps for
their umbrella-header layouts. Screens needs the parent directory of its custom
component descriptors in its header search paths.

Expo Application and Expo Modules JSI 58.0.16 currently lack consumable root manifests.
Their patches provide source targets, including a separate Objective-C target for
Application and Swift/C++ targets for JSI. The local Document Preview module has
its own manifest in the repository.

SQLite has a separate C target for Expo's vendored SQLite build, with the same
session, preupdate, math, API armor, and FTS flags as its podspec. The Swift target
imports that C module explicitly. It discovers production Swift sources automatically
and excludes tests and benchmarks, so newly added implementation files are not omitted.
Application similarly imports its Objective-C
target. A private JSI memory-buffer helper has a distinct name to avoid colliding
with the version serialized into precompiled Expo Core.

Notifications adapts its system presentation callback only under
`EXPO_SWIFTPM_CXX`: Xcode 27's Swift/C++ importer exposes the Objective-C block
argument as `Int`. The patch forwards all option bits to the system callback and
preserves the usual OptionSet signature in other builds.

Expo UI 58.0.21 includes an Objective-C++ touch-handler helper but does not ship an
Apple prebuilt artifact. Its patch splits the helper into an Objective-C++ target
and imports it into the Swift target, allowing Expo autolinking to compile sources.
Screens 4.30.0's manifest includes its new navigation-bar, tab-item coordinator,
and bottom-accessory wrapper sources. Its upstream detached-stack guard replaces
the former local Android header fix.

React Native CSS 3.1.0-rc.0's native wrapper omits React Native 0.88's
`AssetRegistry` export. The patch forwards it lazily in the source and both
published CommonJS wrappers. This restores Expo Asset/font loading used by
Android navigation icons without eagerly evaluating other React Native exports.
`apps/mobile/styles/react-native-css-compatibility.test.ts` verifies the actual
installed wrapper files against this regression.

`scripts/prepare-ios-spm.mjs` runs Expo prebuild without Pods and React Native's
SwiftPM setup. `scripts/wire-expo-spm.mjs` completes the generated consumption
manifests: JSI dependencies, Swift 6 and API Notes, C++ interoperability,
the Router/Screens dependency, implicit Foundation/UIKit imports, and SQLite
benchmark exclusion. A local header
target gives Swift and C++ the same JSI declarations, scopes timing declarations
to C++ and gives the Fabric protocol a single module owner. The generated app
header map exposes codegen headers without eagerly importing community private
headers. Prepare again after dependency or native project changes. Both Xcode
sync entry points check an input fingerprint and require `nub run ios:prepare`
when it changes, so automatic upstream sync cannot overwrite these fixes.

The generated JSI product remains a dynamic library and enables Swift library
evolution to match precompiled Expo Core's ABI. Otherwise the simulator fails at
launch with a missing framework or protocol witness symbol. The app dependency
provider uses an explicit module map for `RCTAppDependencyProvider.h`; the default
directory umbrella incorrectly pulls Foundation into that module under Xcode 27.

The root `components.json` points the shadcn lint plugin at the mobile theme and
UI directory so that contract validation sees the same custom tokens everywhere
in the workspace.

Review these patches and generator workarounds when upgrading either framework.
They are specific to the experimental SDK 58 SwiftPM integration.
